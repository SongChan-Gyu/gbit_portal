# 카카오 알림톡 템플릿 (GBIT Portal)

발송: `src/lib/kakao.ts` → 다이렉트센드 `api_v2/kakao_notice` (`note1`~`note5` 필드).

환경변수 `DIRECTSEND_ALIMTALK_TEMPLATE_NOS`에 **내부 코드 → `user_template_no`** JSON으로 등록합니다.

**다이렉트센드·카카오 템플릿 본문**에서는 보통 `#{비고1}` … `#{비고5}` 형태로 변수를 넣습니다. API로 넣는 값은 `note1`~`note5`이며, **비고 번호와 note 번호가 1:1로 대응**합니다.

**`비고5`(note5)** 는 **v2** 템플릿에서만 포털 URL로 채워집니다(아래 「버전」 참고).

### 알림톡 note 버전 (`ALIMTALK_NOTE_LAYOUT`)

| 값 | 설명 |
|----|------|
| `v1` 또는 **미설정** | 기존 카카오 **승인된** 본문과 동일: 비고5는 빈 문자열, 제주 담당(`JEJU_STAFF` 등)은 note1=`신청자명`에 **투숙 표기명(guestName)**. `src/lib/kakao.ts`의 `directsendNotesForPortalTemplateV1`. |
| `v2` | 신규 검수 본문: 비고5=포털 URL, 제주는 직원/투숙/연도 누적 등. `directsendNotesForPortalTemplateV2`. |

**전환 순서 권장:** 운영은 기본 **v1**로 배포 → 새 템플릿 카카오 검수·`DIRECTSEND_ALIMTALK_TEMPLATE_NOS` 번호 갱신 후 → **`ALIMTALK_NOTE_LAYOUT=v2`** 만 설정.

**v2**일 때 note5 URL: 서버는 `NEXTAUTH_URL`(http로 시작할 때만) → `NEXT_PUBLIC_APP_URL` → 없으면 `https://www.gbitportal.co.kr` 순으로 기준 도메인을 정한 뒤, 휴가·제주 화면에 맞는 경로를 붙입니다. 카카오 검수용 본문 **맨 아래**에 `#{비고5}` 한 줄을 넣어 주세요.

### 포털과 콘솔 템플릿은 어떻게 “맞추나”? (구분·동기화)

**제목(15자)** 과 **내부 코드(`JEJU_APPLICANT_STEP1_OK`)** 는 발송 API에 **실리지 않습니다**. 전송 시 구분에 쓰는 것은 아래 두 가지뿐입니다.

1. **`user_template_no` 연결**  
   카카오·다이렉트센드에서 템플릿을 만들면 템플릿마다 **번호**가 붙습니다. 서버 환경변수 `DIRECTSEND_ALIMTALK_TEMPLATE_NOS`에  
   `{"JEJU_APPLICANT_STEP1_OK":"여기에_콘솔_번호", ...}` 처럼 넣으면, 포털 코드가 그 번호로 바뀌어 `kakao_notice` 요청에 실립니다.  
   → **“이 내부 코드 = 콘솔의 이 템플릿 한 장”** 은 **오직 이 JSON**으로만 맞춥니다.

2. **본문 변수 순서 (`note1`~`note5` ↔ `#{비고1}`~`#{비고5}`)**  
   같은 템플릿 안에서 첫 칸이 누구 이름인지는 **콘솔에 등록한 본문**이 정합니다. 포털은 코드별로 `note1`…`note5`에 값을 채워 보내고, 구현은 `src/lib/kakao.ts`의 `directsendNotesForPortalTemplate`에 고정되어 있습니다.  
   → 콘솔 본문의 **비고 번호 배치**가 아래 **note 매핑 표**와 같으면 “동기화”된 상태입니다. 표나 코드를 바꾸면 콘솔 템플릿도 같이 맞춰야 합니다.

**제목**은 검수·목록에서 사람이 구분하려고 쓰는 이름일 뿐이라, `제주1차승인안내`로 바꿔도 위 JSON·본문만 맞으면 발송은 그대로 됩니다.

### 다이렉트센드에서 `user_template_no`(템플릿 번호)는 어디에 있나?

목록 테이블에는 **한글 제목만 있고 숫자 컬럼이 없는 경우**가 많습니다. 번호는 보통 아래 중 한 곳에 있습니다.

1. **행의 「확인」·상세 보기**를 눌렀을 때 나오는 화면 상단·하단에 **템플릿 번호 / 템플릿 코드 / 등록번호**처럼 표시되는 **숫자** (플랫폼마다 라벨 이름이 다름).
2. **브라우저 주소창 URL** — 상세 페이지로 들어가면 경로나 쿼리에 숫자 ID가 붙는 경우가 있음 (예: `…/template/12345`, `…?no=12345`).
3. 여전히 안 보이면 **다이렉트센드 고객센터·매뉴얼**에 “알림톡 API 발송 시 템플릿 번호 확인” 경로를 문의하는 것이 가장 확실합니다.

한글 제목만으로 API에 넘길 수 있는 값은 없고, 반드시 쪽에서 알려 주는 **숫자(문자열)** 를 JSON에 넣어야 합니다.

번호는 **등록 순서대로 1, 2, 3이 아닐 수 있습니다.** 플랫폼이 부여하는 **고유 ID**(DB 키에 가깝고, 연속 번호·의미 있는 규칙이 없을 수 있음)로 보면 됩니다. 제목과 직접 짝만 맞추면 됩니다.

**지금 스크린에 보이는 제목 ↔ 포털 내부 코드(참고)** — 본문·역할이 같다는 전제에서 매칭하면 됩니다.

| 콘솔 템플릿 제목(예시) | 포털 키 |
|------------------------|---------|
| 휴가 요청 안내 | `LEAVE_REQUEST` |
| 휴가 철회 안내 | `LEAVE_WITHDRAWN` |
| 휴가 결과 안내 | `LEAVE_RESULT` |
| 제주 숙소 1차 승인 안내 | `JEJU_APPLICANT_STEP1_OK` |
| 제주 숙소 최종 확정 안내 | `JEJU_APPROVED` |
| 제주 숙소 반려 안내 | `JEJU_REJECTED` |
| 제주 숙소 취소 안내 | `JEJU_CANCELLED` |
| 제주 숙소 승인자 처리 안내 | `JEJU_STAFF` |
| 제주 숙소 취소 승인자 안내 | `JEJU_STAFF_CANCEL` |

### 템플릿 번호 연결 예시 (다이렉트센드 콘솔 **템플릿 번호** 기준)

카카오 검수 **승인** 후 콘솔에 부여된 번호를 `DIRECTSEND_ALIMTALK_TEMPLATE_NOS`에 넣습니다. 아래는 한 세트 등록 시 화면에 나온 번호와 포털 코드를 맞춘 **예시**입니다(번호는 계정·등록 순서마다 다를 수 있음).

```json
{
  "LEAVE_REQUEST": "3",
  "LEAVE_WITHDRAWN": "6",
  "LEAVE_RESULT": "9",
  "JEJU_APPLICANT_STEP1_OK": "12",
  "JEJU_APPROVED": "15",
  "JEJU_REJECTED": "18",
  "JEJU_CANCELLED": "21",
  "JEJU_STAFF": "24",
  "JEJU_STAFF_CANCEL": "27"
}
```

- **심사상태 승인**이면 발송에 사용할 수 있는 상태로 보면 됩니다.
- **템플릿 상태「대기」**는 **아직 그 템플릿으로 발송 이력이 없을 때** 콘솔에 그렇게 보이는 경우가 많습니다. 첫 발송 후 다른 표기로 바뀌기도 합니다. 검수 **승인** + JSON의 `user_template_no` 일치가 맞으면 API 발송에 문제 없습니다.

## 휴가: 복합 신청일 때 알림톡이 몇 통 나가나?

한 번에 여러 휴가를 넣어도, 시스템은 **결재가 필요한 줄(approvalSteps가 1 이상)** 과 **자동승인 줄(approvalSteps = 0)** 으로 나눠 **LeaveRequest를 최대 2건** 만듭니다.

- **결재가 필요한 묶음이 1개**이면 → 그 묶음당 **알림톡 1통** (결재자 1명에게).
- **복합**이어도 전부 같은 결재선이면 → **여전히 1통**.  
  이때 `휴가유형` 필드는 `연차+오전반차`처럼 **`+`로 이어 붙인 문자열**이고, 기간은 그 묶음 안에서 **가장 이른 시작일 ~ 가장 늦은 종료일**로 한 줄로 갑니다.
- **일부만 자동·일부만 결재**면 → 결재 필요한 쪽만 알림톡이 나가므로, 그 경우에도 **결재 묶음 1개면 1통** (자동 묶음은 알림톡 없음).
- **PM/ADMIN 본인 신청** 등 **전부 자동승인**이면 → 알림톡 **0통**.

즉, “복합이면 매 줄마다 1통”이 **아니라**, “결재가 뜨는 신청 건(그룹)마다 결재자에게 1통”입니다.

## 등록할 템플릿 코드 목록 (총 10종)

제주 입금 기한 초과 **자동 취소**는 스케줄러만 수행하며, **신청자 알림톡은 보내지 않습니다**(신청 화면 안내문으로만 고지).

| 내부 코드 | 용도 |
|-----------|------|
| `LEAVE_REQUEST` | 휴가 결재 요청 → 결재자 |
| `LEAVE_WITHDRAWN` | 휴가 철회(승인 전) → 결재자 |
| `LEAVE_RESULT` | 휴가 승인/반려 → 신청자 |
| `JEJU_APPLICANT_STEP1_OK` | 제주 1차 승인 → 신청자 |
| `JEJU_APPROVED` | 제주 최종 승인(입금확인) → 신청자 |
| `JEJU_REJECTED` | 제주 반려 → 신청자 |
| `JEJU_CANCELLED` | 제주 취소 완료(수동 등) → 신청자 |
| `JEJU_STAFF` | 제주 담당자 — 1차 승인 요청·입금 확인 요청 공통 (`비고4`=입금자명, `비고5`=처리·연도·URL 줄바꿈) |
| `JEJU_STAFF_CANCEL` | 제주 담당자 — 취소 1차·입금 취소 공통 |
| `EXTERNAL_INVITE` | **외부개발자 가입 초대** → 해당 외부 직원 (전화번호로 발송) |

### 카카오·다이렉트센드 **템플릿 제목** (최대 15자)

등록 화면의 **제목**란에는 `JEJU_APPLICANT_STEP1_OK` 같은 **내부 코드를 넣지 않습니다**. (코드는 길고, 제목 제한과 무관합니다. 포털에서는 `DIRECTSEND_ALIMTALK_TEMPLATE_NOS` JSON으로만 코드와 템플릿 번호를 연결합니다.)

제목은 **한글로 짧게** 넣으면 됩니다. 공백도 글자 수에 잡히는 경우가 많으니, 콘솔 카운터가 15를 넘으면 공백을 줄이거나 아래 **짧은 대안**을 쓰세요.

| 내부 코드 | 제목 예시 (일반) | 더 짧게 (공백 없음 등) |
|-----------|------------------|-------------------------|
| `LEAVE_REQUEST` | 휴가 결재 요청 | 휴가결재요청 |
| `LEAVE_WITHDRAWN` | 휴가 철회 안내 | 휴가철회안내 |
| `LEAVE_RESULT` | 휴가 처리 결과 | 휴가처리결과 |
| `JEJU_APPLICANT_STEP1_OK` | 제주 1차 승인 안내 | 제주1차승인안내 |
| `JEJU_APPROVED` | 제주 예약 확정 안내 | 제주예약확정 |
| `JEJU_REJECTED` | 제주 신청 반려 안내 | 제주신청반려 |
| `JEJU_CANCELLED` | 제주 예약 취소 안내 | 제주예약취소 |
| `JEJU_STAFF` | 제주 담당 업무 알림 | 제주담당알림 |
| `JEJU_STAFF_CANCEL` | 제주 취소 업무 알림 | 제주취소알림 |
| `EXTERNAL_INVITE` | 포털 가입 초대 | 포털가입초대 |

`JEJU_APPLICANT_STEP1_OK`는 제목에 **`제주 1차 승인 안내`** 또는 **`제주1차승인안내`**(8자) 정도면 충분합니다.

## note1 ~ note5 매핑 — **v2** (`ALIMTALK_NOTE_LAYOUT=v2`)

v1(미설정)일 때는 비고5가 항상 비어 있고, 제주 담당 템플릿의 비고1은 **투숙 표기명**(`신청자명` 키로 전달)입니다. 상세는 `src/lib/kakao.ts`의 `directsendNotesForPortalTemplateV1` 참고.

| 코드 | note1 | note2 | note3 | note4 | note5 |
|------|--------|--------|--------|--------|--------|
| `LEAVE_REQUEST` | 결재자명 | 신청자명 | 휴가유형 | `시작일(요일) ~ 종료일(요일)` | 포털 URL `/leave/approve` |
| `LEAVE_WITHDRAWN` | 결재자명 | 신청자명 | 요약 | (빈 값) | 포털 URL `/leave/approve` |
| `LEAVE_RESULT` | 신청자명 | 처리결과 | 처리코멘트 | (빈 값) | 포털 URL `/leave/my` |
| `JEJU_APPLICANT_STEP1_OK` | 신청자명(직원) | 투숙객명 | `입실일(요일) ~ 퇴실일(요일)` | 달력연도 누적 신청 건수 문구(아래 참고) | 포털 URL `/jeju/my` |
| `JEJU_APPROVED` | 신청자명(직원) | 투숙객명 | `입실일(요일) ~ 퇴실일(요일)` | `N박 · 입실 M명 · {연도}년 누적 신청 K건` | 포털 URL `/jeju/my` |
| `JEJU_REJECTED` | 신청자명(직원) | 투숙객명 | `입실일(요일) ~ 퇴실일(요일)` | `반려사유 · {연도}년 누적 신청 K건` | 포털 URL `/jeju/my` |
| `JEJU_CANCELLED` | 신청자명(직원) | 투숙객명 | `입실일(요일) ~ 퇴실일(요일)` | `{연도}년 누적 신청 K건` | 포털 URL `/jeju/my` |
| `JEJU_STAFF` | 직원 신청자명 | 투숙객명 | `YYYY-MM-DD ~ … (N박)` | 입금자명만 | `처리단계` + 줄바꿈 + `{연도}년 누적 신청 K건` + 줄바꿈 + 포털 URL (`/jeju/approve`) |
| `JEJU_STAFF_CANCEL` | 직원 신청자명 | 투숙객명 | 동일 | 입금자명만 (취소 1차는 `-` 등) | 동일 (한 필드·세 줄) |
| `EXTERNAL_INVITE` | 이름 | 가입링크 (회원가입 URL) | 만료일 (`YYYY년 M월 D일`) | (빈 값) | (빈 값) |

**`JEJU_STAFF` / `JEJU_STAFF_CANCEL`의 비고5** 는 변수가 **세 줄**입니다(내부에서 `\n`으로 연결). 카카오·다이렉트센드에서 개행이 어떻게 보이는지 **실제 발송으로 한 번 확인**하는 것을 권장합니다.

**제주 「{연도}년 누적 신청 K건」** 은 포털 **내 예약·예약하기** 상단과 같은 규칙입니다. **KST 달력연도** 기준 `createdAt`으로 접수된 건수이며, 상태가 **`REJECTED`·`CANCELLED`** 인 건은 제외합니다. (취소 요청 중 등은 포함.)

## 다이렉트센드에 그대로 복붙할 본문 예시 (**v2**)

아래는 **`ALIMTALK_NOTE_LAYOUT=v2`** 및 새 템플릿 검수용입니다. v1(기존 승인 템플릿)은 비고5 없이 등록된 본문을 그대로 쓰면 됩니다. 카카오 정책에 맞게 문구를 조정해도 되며, **변수 자리**만 `#{비고1}` … `#{비고5}`와 위 v2 표 순서가 일치하면 됩니다.

### `LEAVE_REQUEST`

```
[GBIT Portal]
#{비고1}님, 휴가 결재 요청이 도착했습니다.

• 신청자: #{비고2}
• 휴가유형: #{비고3}
• 기간: #{비고4}

아래 링크에서 확인 후 처리 부탁드립니다.
#{비고5}
본 메시지는 발신 전용입니다.
```

### `LEAVE_WITHDRAWN`

```
[GBIT Portal]
#{비고1}님, 아래 휴가 신청이 철회되었습니다.

• 신청자: #{비고2}
• 내용: #{비고3}
```

## 제주 입금 기한 자동 취소 (알림톡 없음)

- API: `POST /api/cron/jeju-deposit-deadline` (`x-cron-secret` 또는 PM/ADMIN 세션)
- 조건: `status=STEP1_APPROVED` 이고 `depositStatus=NONE` 인 건 중, `step1ApprovedAt`부터 **N일**(기본 5, `JEJU_DEPOSIT_DEADLINE_DAYS`) 경과 시 `CANCELLED` 처리
- **신청자 알림톡은 발송하지 않음** — 신청 화면(`depositDeadlineDays` API 반영)에서 기한·자동 취소만 안내
- GitHub Actions `scheduler-cron.yml` 등에서 동일 API 호출

## `EXTERNAL_INVITE` — 외부개발자 가입 초대 알림톡

외부개발자(고용유형 `EXTERNAL`)는 이메일이 없는 경우가 대부분이므로 알림톡으로 초대합니다.  
관리자 > 사원 관리 > **외부개발자 탭** 에서 「알림톡 초대」 버튼 또는 일괄 발송으로 실행됩니다.

### note 매핑

| note | 내용 |
|------|------|
| note1 (`#{비고1}`) | 이름 |
| note2 (`#{비고2}`) | 회원가입 URL (1회용, 7일 유효) |
| note3 (`#{비고3}`) | 만료일 (예: `2026년 5월 11일`) |
| note4 | (빈 값) |
| note5 | (빈 값) |

### 다이렉트센드 본문 예시

```
[GBIT Portal]
#{비고1}님, GBIT Portal 가입 초대입니다.

아래 링크에 접속하여 아이디·비밀번호를 설정해 주세요.

#{비고2}

※ 링크는 1회만 사용 가능하며, #{비고3}까지 유효합니다.
※ 본인이 아닌 경우 이 메시지를 무시해 주세요. 잘못 전달된 점 죄송합니다.
```

### 카테고리

`서비스이용 → 가입·혜택안내` 또는 `서비스이용 → 업무처리`

## 카카오(다이렉트센드) 카테고리 가이드

검수 지연을 줄이려면 **기타**보다 아래처럼 맞추는 것을 권장합니다. (2단계: 대분류 → 소분류)

| 템플릿 코드 | 권장 카테고리(예시) | 비고 |
|-------------|---------------------|------|
| `LEAVE_REQUEST` | 서비스이용 → **업무처리** 또는 **신청접수** | 결재 요청 |
| `LEAVE_WITHDRAWN` | 서비스이용 → **업무처리** | 철회 안내 |
| `LEAVE_RESULT` | 서비스이용 → **처리결과** (있으면) / 없으면 **업무처리** | 승인·반려 결과 |
| `JEJU_APPLICANT_STEP1_OK` | 서비스이용 → **신청접수** 또는 **예약·결제안내** | 1차 승인·입금 안내 |
| `JEJU_APPROVED` | 서비스이용 → **예약·결제안내** 또는 **처리결과** | 최종 확정 |
| `JEJU_REJECTED` | 서비스이용 → **처리결과** / **업무처리** | 반려 |
| `JEJU_CANCELLED` | 서비스이용 → **예약·결제안내** / **업무처리** | 취소 완료 |
| `JEJU_STAFF` / `JEJU_STAFF_CANCEL` | 서비스이용 → **업무처리** / **신청접수** | 내부 담당자용 |
| `EXTERNAL_INVITE` | 서비스이용 → **가입·혜택안내** / **업무처리** | 외부개발자 가입 초대 |

콘솔에 없는 명칭은 **서비스이용** 안에서 가장 가까운 항목을 고르고, 빨간 안내처럼 **기타만 피하는 것**이 우선입니다.
