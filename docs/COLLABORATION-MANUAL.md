## 0. 처음에 프로젝트 받는 방법 — Cursor에서 Git 주소로 클론

**Cursor 켜고 → 새 프로젝트 만들 때 Git 주소로 클론**하면 됩니다.

1. **Cursor** 실행 후, **File → Clone from Git...** (또는 시작 화면에서 **Clone Git Repository**) 선택.
2. **저장소 URL** 칸에 아래 주소 그대로 붙여넣기:
   ```
   https://github.com/SongChan-Gyu/gbit_portal.git
   ```
3. **저장할 폴더** 정한 뒤 클론 진행. 끝나면 그 폴더가 Cursor에서 열립니다.

이렇게 하면 터미널에서 `git clone` 따로 할 필요 없이, Cursor가 알아서 받아 줍니다.  
(Git이 PC에 설치돼 있어야 합니다. 없으면 [git-scm.com](https://git-scm.com)에서 설치 후 다시 클론.)

**처음 한 번만** Git에 내 이름/이메일을 알려 두면 좋습니다. Cursor 터미널에서:
```bash
git config --global user.name "본인이름"
git config --global user.email "본인@이메일.com"
```

## 1. Cursor (코딩 에디터) — “같은 아이디로 동시 접속” 가능한가?

### 결론: **동시 접속은 권장하지 않습니다**

- Cursor는 **한 계정당 한 곳에서만 로그인**되는 식으로 동작합니다.
- A가 로그인한 상태에서 B가 같은 계정으로 로그인하면, A 쪽이 로그아웃될 수 있습니다.
- 그래서 **같은 아이디로 두 명이 동시에 Cursor 쓰는 건 불가능하다고 보시면 됩니다.**

### 어떻게 하면 되나요?

| 방법 | 설명 |
|------|------|
| **추천** | **각자 Cursor 계정**을 만듭니다. A는 A 계정, B는 B 계정으로 로그인해서 **같은 프로젝트 폴더**를 각자 PC에서 Git으로 받아서 작업합니다. |
| 비추천 | 한 Cursor 계정을 공유하고 “지금 내가 쓸 때는 너는 로그아웃” 식으로 번갈아 쓰는 방법. 동시 작업이 안 되고 꼬이기 쉽습니다. |

**정리**: 같이 유지보수할 거면 **Cursor는 각자 아이디(계정)** 쓰고, **코드는 Git으로만 공유**하는 방식이 안전합니다.

## 2. Git (형상관리) — “코드 같이 쓰기”

Git은 **코드 버전**을 관리하는 도구입니다.  
**아이디는 각자 따로** 씁니다 (GitHub/GitLab 등 계정을 각자 만듦).

### 2-1. 처음 셋팅 (최초 1번만)

- **프로젝트 받기**: 위 **0장**처럼 Cursor에서 **Clone from Git**으로 `https://github.com/SongChan-Gyu/gbit_portal.git` 넣어서 받으면 됩니다.
- **GitHub 계정**: push/pull 할 때 쓰니까 **각자 GitHub 계정** 하나씩 만듭니다. (팀 저장소에 접근 권한 받기)
- **이름/이메일**: 위 0장에 있는 `git config --global user.name` / `user.email` 한 번만 설정해 두면 됩니다.

### 2-2. 평소 작업 흐름 (매일 이렇게 하세요)

- **작업 시작할 때**  
  - 최신 코드 받기:
  ```bash
  git pull
  ```
  - **이걸 안 하면** 남이 올린 코드랑 내 코드가 충돌할 수 있으니, **작업 전에 꼭** 하세요.

- **작업한 뒤 저장소에 올릴 때**
  ```bash
  git add .
  git status        # 올라갈 파일 확인 (선택)
  git commit -m "무슨 작업 했는지 짧게 적기"
  git push
  ```
  - `commit -m "..."` 안에는 **무슨 수정을 했는지** 남이 봐도 알 수 있게 적습니다.  
    예: `"휴가 신청 화면 버튼 문구 수정"`, `"제주 숙소 지도 링크 추가"`

### 2-3. 하지 말아야 할 것

- **작업 전에 `git pull` 안 하고 오래 작업하기**  
  → 나중에 push할 때 충돌 나기 쉽습니다. **시작할 때마다 pull** 하세요.
- **`git push --force` 함부로 쓰기**  
  → 남이 올린 기록을 덮어쓸 수 있어서, **팀원과 상의 없이 쓰지 마세요.**
- **비밀번호, API 키, `.env` 내용을 코드에 그대로 넣고 commit하기**  
  → `.env`는 Git에 올리지 말고, **클라우드/배포 설정**은 아래 3장처럼 따로 공유하세요.

## 3. 클라우드(배포) 계정 공유 — “같은 클라우드 아이디 쓸 때”

배포(호스팅)를 **한 클라우드 계정**으로 같이 쓴다면, 아래만 지키면 됩니다.

### 3-1. 환경 변수·비밀 정보 (.env)

- **`.env` 파일**에는 DB 비밀번호, API 키 등이 들어 있습니다.
- 이 내용은 **Git에 올리지 마세요** (이미 `.gitignore`에 들어 있을 수 있음).
- **공유 방법**:  
  - 팀 내부 **비밀번호 보관 도구**(1Password, Bitwarden 등)나  
  - **문서/채팅으로만** “운영용 .env 값”을 공유하고,  
  각자 로컬에서만 `.env` 파일을 만들어 사용합니다.
- **클라우드 쪽**에는 해당 서비스의 “환경 변수 설정” 화면에 같은 값을 **한 번만** 넣어 두고,  
  **덮어쓰지 말고** 필요할 때만 팀원과 이야기하고 수정합니다.

### 3-2. 배포(Deploy) 할 때

- **한 명이 배포하면** 나머지가 올린 최신 코드가 그 서버에 반영됩니다.
- 그래서:
  - **배포 전에** 반드시 `git pull` 해서 최신 코드 기준으로 배포하고,
  - **“지금 배포한다”** 한 번 팀원에게 알리면, 같은 시간에 다른 사람이 배포 버튼을 누르는 실수를 줄일 수 있습니다.
- **DB 마이그레이션**이 필요한 경우  
  - 배포 스크립트/문서에 “마이그레이션 먼저 실행” 같은 설명이 있으면 그 순서를 지키세요.  
  - (이 프로젝트는 `start:prod` 등에서 migrate 포함되어 있을 수 있음 — `DEPLOYMENT.md` 참고.)

### 3-3. 하지 말아야 할 것

- **클라우드 환경 변수를 혼자 바꿔 두고 팀원에게 안 알리기**  
  → 다른 사람이 “갑자기 안 되는데?” 하게 됩니다. **바꾼 뒤에 꼭 공유**하세요.
- **동시에 두 명이 서로 다른 코드로 배포 버튼 누르기**  
  → **한 번에 한 명만** 배포하고, 나머지는 Git으로 최신 코드만 받아서 쓰는 게 안전합니다.

## 4. 한 페이지로 보는 체크리스트

| 할 일 | 언제 | 한 줄 요약 |
|-------|------|------------|
| Cursor | 항상 | **각자 계정** 사용. 같은 아이디로 동시 접속 X. |
| Git 계정 | 최초 1번 | GitHub 등 **각자 계정** 만들고, `user.name` / `user.email` 설정. |
| `git pull` | **작업 시작할 때마다** | 최신 코드 받기. 안 하면 나중에 충돌. |
| `git add` / `commit` / `push` | 작업 끝났을 때 | `commit -m "무슨 수정인지"` 꼭 적기. |
| `.env` / 비밀번호 | 절대 | Git에 올리지 말기. 팀 내부로만 공유. |
| 클라우드 설정 변경 | 필요할 때 | 바꾼 뒤 팀원에게 알리기. |
| 배포 | 할 때마다 | 한 명만; 배포 전 `git pull` 하고 최신 상태로. |
